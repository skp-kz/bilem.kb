**Статус:** принято 23.10.2026 (Слава). Повод: первый живой онбординг — агент сформировал акт сверки, но ответил «файл переслать не могу, заберите с компьютера». Для клиента это провал: документ в чате — одна из главных услуг.

## Решение

Если инструмент агента вернул файл (`print_invoice`, `print_reconciliation`, `print_power_of_attorney`, дальше — отчёты), файл **приходит в тот же чат документом** вместе с коротким текстом-сводкой. Никаких «заберите с компьютера».

- Отправка файла **самому спрашивающему** (в его чат) — чтение, не действие: доступна всем из белого списка, без `can_act` и без подтверждений.
- Отправка **контрагенту** (`send_document`, почта) — как было: только с правом действий, с подтверждением «да».
- MCP (ChatGPT/Claude) — файл как ссылка на скачивание (подписанная, 24 часа) в тексте ответа.

## Как

1. **Агент** (Земля): в результате инструмента по каналу — кроме текста блок файла: `{ type: "file", name: "Акт сверки … .pdf", mime: "application/pdf", data: base64 }` (до 5 МБ; больше — текст «файл слишком большой»). Локальный MCP — то же самое, стандартный MCP resource/blob.
2. **Облако** (Воздух): файл → R2 (ключ `org/<id>/docs/<uuid>.pdf`, срок хранения 7 дней) → WhatsApp Cloud API `type: document` (upload media → send) / Telegram `sendDocument` → подпись — короткий текст модели (1–2 строки), без пересказа содержимого. Для MCP — подписанная ссылка на R2.
3. Модель не видит байты файла — только имя и факт «файл приложен». Системный промт: «если инструмент вернул файл, он уже отправлен в чат — не говори, что не можешь переслать».
4. Журнал агента: «документ отправлен в чат: имя, кому». Счётчик «Документов отправлено» на главной — отсюда.

## Протокол

Формат блока файла в `result` канала фиксирует Воздух в cloud-channel-protocol первым комментарием в карточке; Земля делает агент по нему. Байты файла в D1 не пишем, только R2.
