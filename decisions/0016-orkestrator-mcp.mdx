## Решение

- Оркестратор агентов пишем **заново**, на **bilem.dev**. Прошлые попытки (runner в Minidesk: inbox/claimed/lease/heartbeat, лимиты шагов) — слишком замороченные, не продолжаем.
- **Доска bilem.dev — единственная правда.** Колонки доски и есть состояния задачи. Сложность добавляем, только когда упрёмся.
- **Всё через MCP, а не через самописные POST/вебхуки.** Любой агент, у которого есть MCP-клиент, подключается к доске и сразу участвует: заводит карточки, комментирует, двигает, **будит других агентов**. Пример: ChatGPT (умеет картинки) по OAuth подключается к MCP bilem.dev, Слава пишет ему «заведи карточку» или «разбуди Куралай / Армана / Монтажника».
- Вход в MCP — **OAuth (Okta / SKP ID)**, как уже сделано у нашего MCP. Заодно практика MCP + OAuth.
- Будить агента = инструмент MCP (условно `wake(agent, card_id)`); как именно доставить звонок конкретному агенту (шлюз OpenClaw у Куры, мост на hermes у Армана, мост `claude -p` для Claude Code) — деталь внутри доски, снаружи один инструмент.
- **Cowork-Claude (советник Славы)** снаружи не будится — архитектура такая. Слава пишет ему «проверь доску», он читает доску через MCP/браузер. Опрос по расписанию — позже, если понадобится.

## Почему

- Переписывание с нуля — привычная практика Славы: так он запоминает, как система устроена, и выкидывает лишнее.
- MCP — стандарт: новый участник (ChatGPT, ещё один агент) подключается без доработки доски.
- База знаний (kb.bilem.ai) и MCP уже есть, пусть лежат в разных местах — это нормально, мы не пишем операционную систему.

## Что отложили

- Отдельный продукт-оркестратор на GitHub — возможно, позже. Сейчас фокус — **Bilem**: пошли бета-тестеры, Инна, Дарья.
- Перепись и подключение всех агентов — большая работа. Пока хватает работы с Землёй через базу знаний (страницы раздела «Стенд»).
- Вебхуки как отдельный механизм — только как внутренняя доставка звонка, не как API.

## Черновой план (когда дойдут руки, по шагу за обед)

1. Перепись агентов: кто, где живёт, как разбудить снаружи, есть ли доступ к MCP доски.
2. MCP доски bilem.dev: инструменты `list_cards`, `get_card`, `create_card`, `comment`, `move`, `wake` — вход по OAuth (Okta), у каждого агента своё имя.
3. Таблица агентов в D1 bilem.dev: имя, способ доставки звонка, вкл/выкл; секреты — через `wrangler secret` (Слава).
4. Каждый звонок — в журнал карточки («разбудили Куру 12:03, ответ 200»); кнопка «Разбудить» в карточке.
5. Пилот на одном агенте (Кура — у неё шлюз уже есть): назначили → проснулась → прокомментировала → «на проверке».
6. Подключить ChatGPT к MCP по OAuth и проверить «заведи карточку» / «разбуди Армана».
7. Остальные агенты по очереди (Арман, Монтажник — монтаж видео, Земля, Воздух).

## Что из этого следует

- Новые разделы «для агентов» делаем как инструменты MCP bilem.dev, а не как отдельные REST-эндпоинты.
- Пока оркестратора нет: задачи Земле — страницами в разделе «Стенд» базы знаний, Слава передаёт их вручную.
