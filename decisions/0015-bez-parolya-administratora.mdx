**Дата:** 19.10.2026 · **Кто:** Стас · **Статус:** предложение, на обсуждение со Славой · Отвечает на открытый вопрос [созвона 17.10](/meetings/2026-10-17) о правах для Enterprise

## Решение (предлагается)

Второй режим онбординга в Bilem Agent — **«без пароля администратора»**. Подключение делится на две части:

| Часть | Кто делает | Чьи права |
|---|---|---|
| Публикация на IIS с OData, пул, права на папку базы | Bilem Agent, как сейчас | Администратор **Windows** (UAC) |
| Расширение с ролями, пользователь `bilem`, состав OData | **Обработка `.epf`**, которую администратор клиента открывает в своём сеансе 1С | Администратор **1С** — в его же сеансе |
| Проверка: что читается, что запрещено | Bilem Agent | Только пользователь `bilem` |

- **Тонкое расширение** — без модулей, форм и HTTP-сервисов, только роли: «чтение» по разделам «Доступа» и «выписка» для белого списка [0013](/decisions/0013-belyj-spisok-zapisi) **без** проведения, отмены проведения, удаления и пометки на удаление.
- **Пользователю `bilem`** назначаются только роли расширения, типовые — нет (кроме минимально необходимых для старта сеанса, если без них нельзя — проверить).
- **Состав OData** обработка только **дополняет**, ничего не удаляет из уже настроенного в базе.
- **Пароль `bilem`** обработка генерирует и показывает один раз — администратор вставляет его в агент.
- **Режим «быстрый»** (пароль администратора 1С → COM) остаётся для массового рынка; «без пароля администратора» — для Enterprise и тех, кто не доверяет программе.

## Почему

- **Проведение запрещено правами самой 1С**, а не только кодом агента: у ролей расширения этого права просто нет — через OData `/Post()` не провести, даже если обойти агент.
- **Обновление типовой не меняет права** — роли расширения оно не перезаписывает (аргумент Стаса с созвона 17.10). Если обновление ломает заимствованный объект, расширение не применяется и `bilem` теряет доступ — отказ в безопасную сторону.
- **Пароль администратора 1С не попадает ни в одну программу** — прямой ответ службе безопасности клиента («бот сам создаёт пользователя с широким доступом без контроля человека»).
- **Обработка открыта**: администратор видит план до выполнения, 1С-ник клиента читает код.
- **Чужие OData-интеграции базы не ломаются** — состав только дополняется.

## Что отвергли / отложили

- **Только ручная инструкция** — много шагов, легко ошибиться в ролях.
- **Типовые роли с подбором через `ПравоДоступа`** для этого режима — при обновлении конфигурации права могут поменяться; роли «ДобавлениеИзменение…» часто несут проведение.
- **Логика в расширении (HTTP-сервисы)** — не нужна: расширение только с ролями, вся логика остаётся в агенте ([0009](/decisions/0009-odata-agent-vmesto-cfe) не меняется).

## Что из этого следует

- **Расширение и обработку делает Стас** — в своём репозитории, на копиях эталонной базы. Партнёру — готовые `.cfe` и `.epf` под MIT и протокол приёмки.
- **В Bilem Agent** (по согласованию со Славой): режим «без пароля администратора» — ввод пароля `bilem`, проверки только под ним (чтение, отказ записи вне белого списка, отказ проведения, 401/403), ежедневная фоновая проверка с подсказкой «перезапустите обработку подключения».
- **Проверить до разработки:** права ролей расширения на заимствованные объекты; нужна ли типовая роль для старта сеанса OData; монопольный режим при записи состава OData; пускает ли БП КЗ внешнюю обработку; поведение после обновления конфигурации.
- **Приёмка на копии эталона:** публикация агентом → обработка → пароль в агент → проверки; `/Post()` под `bilem` — отказ правами; обновление конфигурации на следующий релиз — роли на месте; существующая OData-интеграция — не сломана; «Отключить» — пользователя и расширения нет.
