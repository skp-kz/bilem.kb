**Дата:** 21.10.2026 · **Кто ставит:** Слава · **Исполнитель:** Воздух · **Статус:** к работе

Агентская сторона уже готова: Земля выпустил режим Bilem Cloud в агенте (v0.3.0-beta.14, [часть L](/stand/agent-cloud-mode)) и держит заглушку облака для своих тестов. Теперь нужна **настоящая облачная половина**. Стык — [протокол канала агент ↔ Bilem Cloud](/stand/cloud-channel-protocol), утверждён 20.10: делать **строго по нему**, вопросы и правки — комментарием на странице протокола, не молча. Общий план — [первый клиент Bilem Cloud](/stand/pervyj-klient-darya).

Срочность: появились похожие открытые MCP-коннекторы к 1С. Наше преимущество — облако «из коробки» (WhatsApp, Telegram, ChatGPT без своего ИИ). Делаем быстро и по шагам, каждый шаг — рабочий.

## Что уже есть (твоё)

- Кабинет `app.bilem.ai` — Pages-проект `minidesk/bilem-app`, D1 `bilem-app` (accounts, identities, orgs, org_members, channels, whitelist, link_codes, usage, agent_settings, chat_buffer, memories, agent_events).
- Мозг агента `functions/_agent.js` — Anthropic + инструменты из `_mock1c.js` (выдуманная ТОО «Ласточка Строй»). Telegram работает.
- Вход — Auth0 через `login.bilem.ai` ([вход и аккаунты](/process/vhod-i-akkaunty)).

## Что сделать — по шагам

### Шаг 1. Подключение базы (заявка → кабинет → код → ключ)

- **Миграция D1** (файл в `bilem-app/migrations/`, применяет Слава): `agent_keys` (agent_id, хеш ключа SHA-256, когда выдан, отозван), `connect_requests` (request_id, agent_id, machine, base: slug/конфигурация/названия организаций, хеш кода, срок, попытки, org_id, использован), `base_bindings` (base_id, agent_id, org_id, slug, конфигурация, названия организаций, HMAC БИН/ИИН, state, reason, создано).
- **API для агента** на `mcp.bilem.ai` (разделы 1, 3, 5 протокола): `POST /agent/v1/connect-requests`, `POST /agent/v1/connect-requests/{id}/exchange`, `DELETE /agent/v1/bases/{base_id}`. Ошибки — как в таблице протокола (`code_invalid`, `code_expired`, `code_used`, `too_many_attempts`, `key_revoked`).
- **Страница кабинета `app.bilem.ai/connect?r=…`** (раздел 2): вход → «Компьютер X просит подключить базу Y (в базе: ТОО «…») к вашей организации» → выбор организации, если их несколько → проверка лимита баз по тарифу → код `XXXX-XXXX` (Crockford base32, 10 минут, одноразовый, 5 попыток). Если БИН из заявки не совпал с БИН организации в кабинете — предупреждение «вы подключаете базу другой компании».
- **Кабинет → Настройки:** «Подключённые базы» (база, компьютер, состояние, «Отключить») и «Компьютеры» («Удалить компьютер» снимает **только привязки этой организации**; ключ отзывается, только когда у компьютера не осталось привязок).

### Шаг 2. Канал службы (WebSocket)

- `wss://mcp.bilem.ai/agent/v1/channel` (раздел 4): `hello` / `welcome` / `call` / `result` / `cancel` / `base_state` / `bases` / `ping` / `pong`, коды закрытия `4401`, `4409`, `4429`, `1012`.
- Держать соединения — **Durable Object на компьютер** (по `agent_id`), с WebSocket Hibernation API, чтобы простой не стоил ничего. Отдельный Worker `bilem-mcp` с маршрутом `mcp.bilem.ai`, D1 `bilem-app` — общая с кабинетом. Платные планы Cloudflare не предлагаем — укладываемся во Free (Durable Objects на SQLite там доступны), считаем запросы к D1.

### Шаг 3. Мост: вопросы из мессенджеров — в настоящую 1С

- В `_agent.js` инструменты берутся **от агента**: у организации есть активная привязанная база → `tools/list` и `tools/call` идут через Durable Object в канал (`call` → `result`, дедлайн 60 с, `cancel`, если человек ушёл). Нет привязки — как сейчас, мок «Ласточка Строй» (это демо).
- Несколько баз у организации — модель выбирает базу по названию; одна — без вопросов.
- `caller` в `call`: канал (whatsapp/telegram/chatgpt) и кто спросил — агент пишет это в свой аудит.
- **Отправка документов** (`send_document`): пропускать, только если человек из канала есть в белом списке организации.

### Шаг 4. Пауза и статусы

- Тариф организации не оплачен или превышен лимит баз → `base_state` `paused` (`unpaid` / `limit`), вызовы к базе не шлём, в мессенджере — «доступ приостановлен, проверьте кабинет».
- Отключили в кабинете → `revoked`. Нет связи с агентом → в кабинете «нет связи с … минут».
- Тариф пока ставится вручную из bilem.dev → Клиенты («Бета-тестер» — всё включено, со сроком).

### Потом (не в этой задаче)

Облачный MCP для ChatGPT / claude.ai (`https://mcp.bilem.ai/<org>`, OAuth через Auth0, авторизация по тарифу) и WhatsApp через номер Zadarma — отдельными задачами после шагов 1–4.

## Правила данных

- **БИН/ИИН** из заявки — только для опознания базы и сверки с кабинетом; хранить **только HMAC** (секрет `BIN_HMAC_KEY`), в кабинете не показывать — организации только по названию.
- **Ключ компьютера** — в D1 только хеш. Код — одноразовый, 10 минут, 5 попыток.
- **Ответы инструментов** (данные 1С) отдельно не хранить — только внутри переписки (`chat_buffer`) по сроку из политики (по умолчанию 24 ч, клиент меняет 0–30 суток).
- Политика конфиденциальности уже это описывает (строка «Подключённые базы 1С») — если меняешь, что хранится, сначала скажи Славе.

## Секреты и деплой (делает Слава)

- Новые секреты: `BIN_HMAC_KEY` (случайная строка 32+ байт) — назови точную команду `wrangler secret put` для Worker `bilem-mcp`.
- Миграции D1 и деплой — Слава; ты даёшь команды целиком, с `cd`.
- DNS `mcp.bilem.ai` — маршрут Worker в зоне bilem.ai (Cowork может завести в Cloudflare, скажи).

## Как проверить

1. Заглушка Земли больше не нужна: агент на стенде с адресом облака `https://mcp.bilem.ai` (конфиг агента) → «Подключить…» → кабинет → код → база в облаке, статус «Работает».
2. В Telegram тестовой организации: «кто нам должен?» — ответ из настоящей 1С стенда, не из «Ласточки».
3. Отключить базу в кабинете → агент показывает «Отключена в кабинете»; Telegram отвечает «база не подключена».
4. Поставить тариф «не оплачен» → «На паузе — проверьте кабинет» в агенте, «доступ приостановлен» в Telegram.
5. Перезагрузить сервер стенда → служба сама переподключилась, вопросы снова идут.

## Что сдать

- Код (`bilem-app`, новый Worker `bilem-mcp`), миграция, команды Славе (миграция, секрет, деплой).
- Запись в журнал — `stand/vozduh-cloud-side-log` (новые записи сверху): что сделано, что проверено, отклонения от протокола (если были — согласованы).

## Чего не делать

- Не менять протокол молча — только через страницу протокола и Славу.
- Не хранить БИН/ИИН в открытом виде и данные 1С вне переписки.
- Не открывать ничего входящего к клиенту — канал открывает только агент.
- Не предлагать платные планы Cloudflare; не делать оплату картой — тариф пока вручную.
- Не трогать мок «Ласточка Строй» как демо — он остаётся для организаций без привязанной базы.
