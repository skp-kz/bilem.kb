## 22.10.2026 (tools/list) — Codex входит, но не видит инструментов (#59)

**Статус:** сделано в коде, проверено локально, **не задеплоено**. Коммит `442d440` в `skp-kz/minidesk`.

**Симптом.** OAuth из настольного ChatGPT (Codex) прошёл. В аудите есть `initialize` и `tools/list`, но модель инструментов Bilem не видит.

**Что нашли**

- Список инструментов не мог быть пустым: `bilem_status` облако добавляет всегда. Схемы проверены: имена `[a-z_]`, `inputSchema` с `type: object`, лишних полей нет.
- Узкое место — время ответа. Codex ждёт запуска сервера (`initialize` + `tools/list`) 10 с (`startup_timeout_sec`), дальше работает без его инструментов. Облако ждало `tools/list` от агента до 20 с + 2 с. В аудите время `tools/list` не писалось, поэтому подтвердить по журналу нельзя.

**Что сделано**

- Дедлайн `tools/list` к агенту — 6 с.
- Запасной список в Durable Object: последний ответ агента по базе. Если ответа нет — имена инструментов из `hello` агента, схемы из каталога `tools.js`.
- Аудит `tools/list`: `tool = n=<число инструментов>`, `ms` и источник списка в `error` (`cache:timeout`, `hello:offline`, …). Миграция не нужна.

**Проверено:** `node tools/bilem-mcp/test.mjs` — всё проходит, добавлены проверки на запасной список и аудит.

## 22.10.2026 (правки) — облачный MCP: OAuth 2.1 и адрес `/<org>` (#59)

**Статус:** сделано в коде, проверено локально, **не задеплоено**. Коммит `cc7fc12` в `skp-kz/minidesk`. Заменяет секретную ссылку из записи ниже (решение Славы 22.10).

**Адрес.** MCP организации — ровно `https://mcp.bilem.ai/<org>`.

- Эту строку (`org.mcp_url`) кабинет отдаёт агенту при обмене кода. Агент beta.16 показывает её клиенту, его не меняли (согласовано с Землёй).
- `/<org>/mcp` — синоним.
- Слаги `agent`, `oauth`, `mcp`, `api`, `authorize`, `token`, `register`, `revoke` зарезервированы.

**Вход — OAuth 2.1 по спецификации MCP** (`tools/bilem-mcp/oauth.js`). `mcp.bilem.ai` — одновременно ресурс и сервер авторизации.

- Без токена `/<org>` отвечает `401` с `WWW-Authenticate`. Заголовок указывает на `resource_metadata` — `/.well-known/oauth-protected-resource/<org>`.
- Метаданные:
  - `/.well-known/oauth-protected-resource/<org>` (RFC 9728);
  - `/.well-known/oauth-authorization-server` (RFC 8414).
- `/oauth/register` — DCR (RFC 7591): публичные клиенты (`none`) и клиенты с секретом.
- `/oauth/authorize` — `code`, обязательный PKCE S256; организацию задаёт `resource`.
  - Если человек не вошёл — вход на `app.bilem.ai` (login.bilem.ai, Auth0, тот же аккаунт, что в кабинете) и возврат обратно. Worker читает cookie входа на `.bilem.ai`.
  - Экран согласия «ChatGPT просит доступ к 1С»: организация, домен возврата. Без `resource` — выбор организации.
- Кто даёт доступ: владелец или админ организации. Доступ = аккаунт + организация + клиент.
- `/oauth/token`: `authorization_code` и `refresh_token` с ротацией. Access живёт 1 ч, refresh — 90 дней. Есть `/oauth/revoke`.
- Токены, коды и секреты клиентов — в D1 только как SHA-256, KV не нужен. Пользователь токенов не видит.
- При каждом вызове проверяется:
  - доступ не отозван;
  - организация совпадает с адресом;
  - человек всё ещё владелец или админ.

**Кабинет → 1С-Базы → Bilem Cloud → «ChatGPT и Claude»:**

- адрес MCP и кнопка «Копировать»;
- подключённые клиенты: кто разрешил, когда, последний вызов;
- «Отозвать» удаляет токены сразу.

В аудите — e-mail и клиент. `caller.user` для агента — e-mail.

**Проверено:** `node tools/bilem-mcp/test.mjs` — 54 проверки:

- метаданные, `401`, DCR;
- полный поток «вход → согласие → code → token»;
- PKCE, одноразовый код;
- «Отклонить»; не-админ → `403`; чужой `redirect_uri`;
- ротация refresh;
- токен чужой организации → `401`;
- отзыв в кабинете → `401`; потеря роли → `401`.

Сборка кабинета и `test-cloud-connect.mjs` проходят.

- миграция `2026-10-22-cloud-mcp.sql` переписана (`cloud_oauth_*` вместо ссылок). Если прошлую версию уже применяли — команда очистки в карточке #59;

1. Кабинет → «ChatGPT и Claude» → скопировать `https://mcp.bilem.ai/akyl`.
2. Добавить адрес в ChatGPT (Режим разработчика → Создать, аутентификация OAuth) или в Claude (Коннекторы → Добавить свой).

## 22.10.2026 — канал агента и облачный MCP для ChatGPT/Claude (#59)

**Статус:** сделано в коде, проверено локально, **не задеплоено**. Коммит `3f1be18` в `skp-kz/minidesk`.

**Что сделано**

- **Worker `bilem-mcp`** (`tools/bilem-mcp`) на `mcp.bilem.ai`:
  - канал `wss://mcp.bilem.ai/agent/v1/channel` — Durable Object `AgentChannel` на компьютер (`idFromName(agent_id)`), SQLite, WebSocket Hibernation, поэтому простой ничего не стоит (Free);
  - остальное `/agent/v1/*` (заявки, обмен кода, отключение) Worker проксирует в Pages `bilem-app` с `X-Bilem-Host: mcp.bilem.ai`.
- **MCP организации** `https://mcp.bilem.ai/<org>/mcp/<секрет>` — Streamable HTTP, ответы JSON без SSE:
  - методы `initialize`, `tools/list`, `tools/call`, `ping`;
  - инструменты приходят от агента, только по активным базам этой организации (`cloud_bases.state = 'active'`); у агента — своя проверка;
  - одна база — аргумента `base` нет; несколько — `base` обязателен, значения — slug'и баз;
  - служебный инструмент `bilem_status` — базы и связь с компьютером;
  - `send_*` из ChatGPT/Claude закрыт: у них нет белого списка (решение 20.10, п. 6);
  - `caller.channel` — `chatgpt`/`claude` по клиенту, `caller.user` — `mcp-link:<id>`.
- **Кабинет → 1С-Базы → Bilem Cloud → «ChatGPT и Claude»**:
  - «Выпустить ссылку» — показывается один раз, в D1 только SHA-256, не больше 5 на организацию;
  - «Отозвать» — ссылка перестаёт работать сразу;
  - «Вызовы из ChatGPT и Claude» — последние вызовы.
- **Аудит** `cloud_mcp_audit`: ссылка, канал, клиент, метод, инструмент, база, успех или ошибка (`offline`/`timeout`/`denied`/…), время в мс. Ответов 1С в журнале нет.
- **Кабинет → агент сразу**:
  - «Отключить» базу → `base_state revoked/cabinet` по каналу;
  - «Удалить компьютер» → `base_state` по каждой базе, а если привязок не осталось — закрытие `4401`;
  - Pages достаёт Durable Object через binding `AGENT_CHANNEL` (`script_name: bilem-mcp`).
