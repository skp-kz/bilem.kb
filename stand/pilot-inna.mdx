## Контекст

Инна (Protax, бухгалтерская компания) — первый бета-тестер ([встреча 20.10](/meetings/2026-10-20)). Режим **Developer**: Bilem Agent рядом с базой + её OpenClaw, агент **Саги**, по MCP. Саги в одной сети Tailscale с её базами. Главная функция для неё — **акт сверки**: его чаще всего просят клиенты, и больше всего он отвлекает бухгалтера.

## Исходные

- Копия одной базы Инны — Слава передаст на стенд приватно. Конфигурацию, релиз и вид базы (файловая или серверная) уточнить при получении.
- Bilem Agent — текущий релиз (не ниже `v0.3.0-beta.12`).
- Акт сверки уже есть: `print_reconciliation` и `send_document` ([ТЗ v0.3, часть E](/stand/agent-app-v03)).

## Шаги

1. **Развернуть копию на стенде** и подключить Bilem Agent: все 9 шагов проверки зелёные. Если состав OData неполный (как на боевом сервере — без «Хозрасчетного»), разобраться, доработана ли конфигурация, и записать вывод в журнал.
2. **Акт сверки на её данных.** 5–10 контрагентов с движением, разные периоды (квартал, полугодие, год), с несколькими договорами и без. Сверить с типовым отчётом «Акт сверки» этой же базы: сальдо на начало и конец, обороты, число документов — **до копейки**. Расхождения — разобрать и исправить.
3. **Тексты и форма.** Проверить, что PDF акта читается бухгалтером без правок: реквизиты обеих сторон, итог прописью, подписи. Замечания — списком для Славы.
4. **Подключение OpenClaw (Саги).** Проверить сценарий «агент OpenClaw вызывает Bilem Agent по MCP через Tailscale» ([подключение через Tailscale](https://docs.bilem.ai/connect/tailscale)). Подготовить для Инны короткую инструкцию: что поставить, какой адрес MCP дать Саги, как проверить.
5. **Отправка.** «Сделай акт сверки с … за квартал и отправь им» — с предпросмотром перед отправкой (`send_document`, почта стенда).

## Что сдать

- Журнал `stand/pilot-inna-log` (новые записи сверху): что сделано, расхождения и как исправлены, релиз, если были правки.
- Инструкция для Инны: подключение Саги к Bilem Agent.
- Готовность к установке у Инны на её сервере — по команде Славы.

## Что нельзя

- Выносить базу Инны со стенда и копировать её куда-либо ещё.
- Писать в журнал, коммиты, тесты и issue названия контрагентов, БИН, суммы и любые данные из базы — только обезличенно («контрагент 3, квартал III: сходится»).
- Отправлять письма на реальные адреса контрагентов из базы — только на почту стенда.
- Подключаться к серверам Инны напрямую — только через Славу.
- Копию базы удалить по команде Славы после пилота.
