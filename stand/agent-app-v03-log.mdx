- **Решение Славы 20.10:** дополнительный пароль на настройки — для серверов, где работают несколько администраторов (аутсорсеры). Место — «Настройки…» → «Сервис» → блок **«Защита настроек»** сразу под «Обновлениями» (не отдельной вкладкой: это служебная настройка, вкладок и так восемь).
- **Где спрашивается:** до открытия окна настроек и перед «Скопировать адрес MCP» (в адресе — токен). Окно в трее и «Перезапустить MCP» — без пароля. Командная строка пароль не спрашивает (ею пользуется администратор компьютера).
- **Хранение:** только хеш PBKDF2-SHA256 с солью (100 000 итераций), сравнение за постоянное время; после 5 неверных попыток — пауза минуту. Задать / сменить (с текущим паролем) / снять — в блоке; минимум 4 символа.
- **Журнал:** вход в настройки, неверные попытки, задание, смена и снятие пароля — с учётной записью Windows (видно, кто из администраторов что трогал).
- **Забыли:** администратор компьютера снимает пароль командой «bilem-agent reset-settings-password» (строка в журнале).
- Попутно: отчёт для поддержки больше не содержит зашифрованный пароль почты и хеш пароля настроек.
- Проверено на стенде: блок на «Сервисе», окно пароля до настроек, «Отмена» — окно не открывается, сброс из командной строки, строки журнала. Заметки к релизу на GitHub поправлены после выпуска (в строку команды попал управляющий символ).

### Часть G — `receivables` / `payables`

- **Долг** — по регистру «Типовой»: сальдо 1210 по контрагенту и договору минус аванс 3510 по тому же договору (кредиторка: 3310 минус 1710). Плюс в ответе остаток 1210 и 3510 так, как его считает оборотно-сальдовая ведомость, — для сверки с ОСВ.
- **По каким документам:** непогашенные реализации (FIFO — оплаты закрывают самые старые) — номер, дата, сумма, оплачено, остаток, дни, **счёт-фактура** (по основанию). До 10 документов на контрагента. Корзины 0–30 / 31–60 / 61–90 / 90+.
- **Отборы:** «больше N дней» (min_days), «не оплатили с прошлого месяца» (issued_before = 1-е число текущего месяца — подсказка модели в описании), контрагент, организация, минимальная сумма, top.
- **Дата данных** и давность выписок — в каждом ответе, предупреждение «должник мог уже заплатить» первым. ИИН контрагентов-физлиц не показывается. Номера документов и счета-фактуры — только у видов, включённых на «Доступе».
- На учебной базе стенда: 27 должников, ответ ~1,5 с; отборы и разбивка по договорам проверены вручную. Приёмка Славы — итог против ОСВ по 1210 на боевой базе.
- Попутно: из состава OData для БП КЗ убраны объекты российской бухгалтерии (строки «нет в конфигурации» больше не появятся); при повторной настройке базы на новом компьютере роли bilem для служебных данных больше не называются «лишними».

### Часть I — служба Windows

- **Служба «Bilem Agent»:** LocalSystem, автоматический отложенный запуск, при сбое — перезапуск через минуту (три раза), сброс счётчика через сутки. Внутри — MCP на 127.0.0.1 по тому же адресу и токену, фоновые проверки баз, проверка обновлений, строка «Обновлено с X на Y» после установки. MSI ставит и запускает её; без .NET 4.8 служба регистрируется, а стартует сама после установки .NET и перезагрузки (иначе установка откатилась бы).
- **Окно без прав администратора**, автозапуск при входе любого пользователя (у каждого сеанса RDP — свой трей). Показывает службу, MCP, проверки баз и журнал службы; состояние берёт у службы по именованному каналу (читать — вошедшие пользователи, команды — только администратор). Кнопки со щитом (UAC): «Настройки…» — прежнее окно со всеми вкладками, «Скопировать адрес MCP», «Перезапустить MCP», «Запустить службу».
- **Почему «Настройки…» одной кнопкой, а не щит на каждой:** все вкладки пишут настройки и секреты, которые закрыты для обычных пользователей (иначе любой вошедший по RDP читал бы токен MCP и пароль почты). Одно окно с UAC закрывает подключение базы, IIS, COM, «Доступ», печатные формы, почту, обновление и откат.
- **Папка документов** — C:\\ProgramData\\Bilem\\Документы(база)\\… (у службы нет «Документов» пользователя), меняется в «Печатных формах» → «Общее». Читать — «Пользователи», писать — Администраторы и служба. Прежние PDF остаются в «Документах» пользователя.
- **Обновление кнопкой:** помощник закрывает все окна агента (во всех сеансах), MSI останавливает службу, ставит, запускает; окно открывается снова уже без прав. Обновление с beta.9 (без службы) тоже работает: окно, запущенное прежним помощником с правами, само перезапускается без них.
- **Проверено на стенде:** установка beta.9 → обновление на beta.10 тихой установкой; служба (тип запуска, учётка, восстановление) — как в ТЗ; MCP из службы отвечает (10 инструментов, receivables по учебной базе); печать счёта из службы → PDF в общей папке с правами «Пользователи — чтение»; трей без прав — снимок; «Перезапустить MCP» через службу; удаление — служба и автозапуск удалены, данные остались.
- **Не проверено на стенде:** перезагрузка без входа (стенд не перезагружаю) и окно UAC на защищённом рабочем столе — это приёмка Славы на сервере.
- README: «что меняет в системе» — служба, автозапуск, папка документов.

### Почему публикация на сервере падала (решено)

Модуль веб-сервера 1С 8.3.24 на Windows Server 2016 (контроллер домена) падал в IIS на первом же запросе — в агенте это выглядело как «HTTP 0» на шаге проверки. **Причина — у пула IIS была выключена загрузка профиля учётки.** Модулю 1С профиль нужен при старте; без него он не создаёт служебный объект и падает. Включили профиль — заработало. На стенде то же не ловится: там Server 2025, и это не контроллер домена. Теперь агент сам создаёт пул с профилем и без .NET (модулю 1С он не нужен), обе настройки видны в «Диагностике». По дороге исключили: Tumar CSP и Java, настройки платформы, .NET в пуле. Разбор по шагам — в записях ниже.

## 19.10.2026 · Причина найдена: у пула не загружался профиль учётки. База на боевом сервере подключена

<Check>
  На боевом сервере: проверки базы — **ГОТОВО** (чтение, запрет записи — отказ 1С, без пароля 401, снаружи 403). В агенте — коммит **`67d1f59`** (`main`), тесты **158 из 158**, на стенде v19–v21 — ГОТОВО.
</Check>

- **Причина:** у пула публикации была выключена загрузка профиля учётки (loadUserProfile=false). Модулю веб-сервера 1С 8.3.24 на Windows Server 2016 (контроллер домена) при старте нужен профиль учётки пула. Без него модуль не создаёт служебный объект и падает на первом запросе: пустой указатель по смещению 0xb575 из дампа, «HTTP 0» на шаге проверки. Включили профиль — публикация заработала сразу.
- **Почему не поймали на стенде:** там та же настройка, но работает — Server 2025 и не контроллер домена.
- **Как избегаем дальше:** агент создаёт пул с загрузкой профиля и без управляемого кода, в «Диагностике» обе настройки проверяются. Отсутствие веб-модулей у платформ, которые не публикуют базы, теперь справочно, а не красным (на сервере было 4 ложных красных).
- **Исключено по ходу:** Tumar CSP и Java (в процессе их нет), настройки платформы (conf не менялся с 2024 года), .NET в пуле (без него падало так же). «Не открываются сайты» — правило брандмауэра «SKP 1C Shield» (локальная защита сервера), не вирус.
- **Открыто:** сборка hpdx в процессе IIS (запись ниже) — Слава уточнит у своего администратора; состав OData без Хозрасчетного; возврат регистрации COM на 8.3.15 — по решению Славы.

## 19.10.2026 · Мини-дамп w3wp с боевого сервера: стек, модули; пул без .NET — в `main`

<Check>
  Коммит **`119c825`** (`main`), тесты **158 из 158**. На стенде пулы v19–v21 переведены в режим «Без управляемого кода» — все проверки ГОТОВО. Дамп разобран на стенде (WinDbg, символы Microsoft). Дамп и вывод отладчика остались в рабочей папке стенда, наружу не уходили.
</Check>

### Что в дампе

- **Место падения:** смещение 0xb575 в wsisapi — чтение по нулевому указателю. Перед этим вызывается внутренняя функция модуля (смещение 0xc670): она вернула пустой указатель, и код сразу вызывает метод этого объекта. Символов 1С нет, кода модуля в мини-дампе нет — имя функции не определить. Это логика самого модуля 1С: что-то, что он ждёт при старте обработки запроса, не создалось.
- **Ядро 1С одной версии:** wsisapi, core83, nuke83, techsys, xml2, xdto, json, ICU, рантайм C++ — все из папки 8.3.24.1342. Чужих версий платформы в процессе нет.
- **Tumar CSP и Java в процессе нет** (172 модуля, ни одного из папок GammaTech или Java). Гипотезу снимаю.
- **Главное отличие от стенда:** в процессе пула 1С на сервере поднят полный домен ASP.NET для нашей публикации. В нём System.Web, System.Web.Extensions, WPF (PresentationCore, PresentationFramework, WindowsBase, System.Xaml), Microsoft.JScript, Microsoft.Build.Utilities. И ещё сборка **hpdx**: управляемая, примерно 750 методов, загружена **из памяти** (у модуля нет файла на диске). Она крутит фоновую задачу — цикл с паузами. На стенде пул bilem грузит только загрузчик ASP.NET, управляемый код там не стартует вовсе.
- **IIS на сервере не новый:** в Default Web Site работает RD Web Access (порт 443), там же три прежних приложения и пулы .NET 4.5. В конфигурации IIS из архива лишних модулей нет. Значит, управляемый код подмешивается на уровне ASP.NET: файлы конфигурации .NET на машине или файл конфигурации корня сайта, который наследуют все приложения сайта.

<Warning>
  **Сборка hpdx, загруженная из памяти в рабочий процесс IIS, — повод проверить безопасность сервера.** Это не вывод о взломе: так работают и некоторые легальные агенты мониторинга. Но тем же приёмом пользуются бэкдоры, внедрённые в IIS, а сервер — контроллер домена с открытым RD Web Access. Что проверить администратору, ничего не удаляя:

  1. Файлы конфигурации .NET 4 на машине (machine и корневой web) и файл конфигурации корня Default Web Site. Разделы модулей, сборок компиляции, провайдеров сборки — всё незнакомое, особенно со ссылкой на hpdx.
  2. Поиск файлов hpdx по дискам. Страницы и обработчики ASP.NET, папки App_Code и bin в корне сайта и в папках прежних публикаций — даты изменения.
  3. Полная проверка Microsoft Defender или другим антивирусом.
  4. Если что-то найдено — к специалисту по безопасности. Дамп и файлы наружу не отправлять.
</Warning>

### Что сделано

- **Пул публикации — «Без управляемого кода»:** модулю 1С (ISAPI) .NET не нужен. Так в процесс 1С не попадает ни ASP.NET, ни чужие модули уровня машины. Проверено на стенде: OData, запрет записи, 401 и 403 — как раньше; CLR в процессе пула больше нет. В «Диагностике» — строка «Пул без управляемого кода». Повторная настройка базы переводит существующий пул.
- **Ожидание:** по дампу самая вероятная версия — wsisapi падал из-за управляемого кода в процессе. Если так, на сервере публикация заработает. Если упадёт и без CLR — следующий шаг: техжурнал 1С на время одного запроса.

### Как проверить на сервере до beta.5 (по команде Славы)

В диспетчере IIS: пулы приложений → пул Bilem нашей базы → «Основные настройки» → версия .NET CLR — «Без управляемого кода». Затем в агенте — «Проверить» по базе. Меняется только наш пул, остальные сайты и пулы не трогаются. Вернуть — выбрать .NET CLR v4.0.

### Что сделано

- **Вкладка «SMTP»** — после «Печатных форм», на каждую базу: сервер, порт, SSL/TLS (465) или STARTTLS (587), логин, **пароль приложения** (в окне — точки, хранится только зашифрованным для этой машины — DPAPI; поле очищается после сохранения, рядом — «сохранён»), имя и адрес отправителя; готовые подсказки Gmail / Mail.ru / Yandex / Outlook (сервер, порт, где взять пароль приложения); **«Проверить — письмо себе»**; **«Свои адреса»** (адрес — кто, по одному в строке); скрытая копия себе (вкл. по умолчанию); лимиты 10 / час, 50 / день; шаблоны темы и текста РУ / КЗ с подстановками и подпись; рубильник **«Почта выключена»** (и в меню трея); серый блок «Подтверждение с телефона, права по людям, цепочки одобрений · Облако».
- **Свой SMTP-клиент** (без сторонних библиотек): `System.Net.Mail` не умеет SSL сразу при подключении (465 — Mail.ru, Яндекс). SSL сразу и STARTTLS, AUTH PLAIN/LOGIN, письмо «текст + PDF», кириллица в теме и имени вложения — RFC 2047. В тексте ошибки сервера пароля нет.
- **`send_document`** (`base`, `document: invoice`, `number` / `last`, `counterparty`, `to`, `note` ≤ 300): делает PDF счёта → письмо **ждёт подтверждения**: окно агента поверх остальных + уведомление в трее; в окне — первая страница PDF, «Открыть PDF», кому (несколько e-mail у контрагента — выбор), скрытая копия, тема, текст → **«Отправить» / «Отмена»** (мимо модели; крестик = «Отмена»). Ответ ИИ — `id` и «ждёт подтверждения», адрес — замаскирован. Итог — **`send_status(id)`**: pending / sent / cancelled / failed (текст SMTP).
- **Адресат — только из двух мест**: e-mail контрагента счёта из 1С или «Свои адреса»; любой другой — «адрес не найден ни в карточке контрагента, ни в своих адресах — добавьте его во вкладке SMTP». `to` не указан — e-mail контрагента из 1С. Один адресат + скрытая копия; вложение — только PDF агента.
- **E-mail контрагента из 1С**: регистр «Контактная информация» — **служебный объект** состава OData: в дереве «Доступа» его нет, инструментам ИИ он недоступен (там и данные физлиц), читается только внутри агента фильтром «этот контрагент + тип «адрес эл. почты»» (`Объект eq cast(guid'…', 'Catalog_Контрагенты')` — составной тип, простое `guid'…'` 1С не принимает). Добавляется при настройке базы; v19, v20, v21 перенастроены (состав 44, «Доступ» не сброшен, ложных «изменений» нет).
- **Журнал агента**: «Счёт №4 от 13.04.2022 (v21) отправлен на t\*\*\*@…, подтвердил …, 18.10 15:41»; отмена и ошибки — так же; содержимого письма нет. Для лимитов хранятся только времена отправки.
- В режиме `serve` (без окна) подтвердить некому — `send_document` отказывает с просьбой открыть окно. Очередь живёт, пока окно открыто. Доверенности и акты сверки (только на «Свои адреса») — когда появятся их печатные формы; сейчас `document` — только `invoice`.
