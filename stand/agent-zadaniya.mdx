Отдельный релиз на каждый пункт не нужен.

### 0.3.1-beta.4 — 23.10.2026, stand #77

Коммит `c7e87a4`, ветка `agent-0.3.1-beta.4`, PR skp-kz/bilem.ai#10 (поверх #9), пре-релиз `v0.3.1-beta.4`. Работает только с сервером, где есть формат v1.1: `code` в ответе `connect-requests` и опрос `GET …/{id}` (stand #77).

- [x] **Один код подключения — вторая редакция (0017, обновлено 23.10 вечером; заменяет beta.3).** Направление наоборот: код рождается **в агенте**, подтверждает **владелец на телефоне**. Окно «Подключить…»: агент создаёт заявку (`POST /agent/v1/connect-requests`), показывает **код подключения** из ответа (`code`, короткий) + «Скопировать» + «Действует 10 минут» + подпись «Вставьте код в кабинете app.bilem.ai → 1С-Базы → Подключить базу. Владелец подтвердит на телефоне». Поля «Код из кабинета» / «Подключить» и «Открыть в браузере» — нет. Затем агент опрашивает `GET /agent/v1/connect-requests/{id}`: «ждём подтверждения владельца…» → `approved` (с ключом) → «подключено»; `declined` / `expired` → «Получить новый код». `POST /agent/v1/connect` из beta.3 не используется. Формат ответа облака — у Воздуха в stand #77. Спецификация: kb.bilem.ai/decisions/0017-odin-kod-podklyucheniya. (Слава, 23.10) — `c7e87a4` (Земля, 23.10). Сделано по формату v1.1 Воздуха (#77). Вместо «Действует 10 минут» — отсчёт «Действует ещё 9:41». В состоянии `waiting_owner` окно показывает название кабинета. Повтор после `declined` / `expired` / `failed` — кнопка «Подключить…» (по таблице Воздуха), а не «Получить новый код». Ключ `--code` в CLI убран: `cloud connect --slug` печатает код и ждёт «Разрешить».
