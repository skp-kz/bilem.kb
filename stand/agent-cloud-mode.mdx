## Правка 21.10 — видно, что сверху бесплатно, снизу платно (Слава)

Смотрел вкладку MCP в beta.14: разницу между блоками не видно. Сделать:

- **Блок 1** — заголовок «MCP на этом компьютере» + справа в заголовке зелёная плашка **«Бесплатно»**. Под адресом мелко: «Открытый код (MIT), без ограничений».
- **Блок 2** — заголовок «MCP в облаке — Bilem Cloud» + справа в заголовке плашка цвета охры **«Коммерческая лицензия»**. Первая строка описания: «Платно, по подписке. Условия и оплата — в кабинете app.bilem.ai». Дальше — как сейчас (WhatsApp, Telegram, ChatGPT, claude.ai…).
- Окно подтверждения при включении: «Включить Bilem Cloud (коммерческая лицензия)? Локальный бесплатный MCP на этом компьютере будет выключен. Продолжить?»
- Строка состояния в режиме Cloud: «Bilem Cloud · коммерческая лицензия · баз в облаке: N из M»; в бесплатном — «MCP · бесплатно · порт 8796 · баз: N».
- Тексты — в `Strings.resx` (RU/KZ). Цены, тариф и сроки в агенте по-прежнему не показываем — только слова «бесплатно» / «коммерческая лицензия».

## Принципы (Слава)

- **Либо бесплатно, либо платно.** По умолчанию — бесплатный режим (локальный MCP `127.0.0.1`). Включили Bilem Cloud — локальный MCP выключен. Одновременно агент оба режима не держит. Переход в обе стороны — без переустановки.
- **Отдельной вкладки «Bilem Cloud» нет** — всё на вкладке **MCP**.
- **Тарифа в агенте нет** (название, срок, лимиты — только в кабинете). В агенте — только статусы и пометка «бесплатно / коммерческая лицензия».
- **Каждая база подключается к облаку отдельно**: на сервере может быть сотня баз, в облако идёт только подключённая.

## Вкладка MCP

**Блок 1 «MCP на этом компьютере — бесплатно»** — как сейчас (статус, адрес с токеном, «Скопировать», «Остановить», ссылка docs.bilem.ai/connect). Когда включён Bilem Cloud — весь блок серый, кнопки недоступны, статус «Выключен — включён MCP в облаке», порт не слушается.

**Блок 2 «MCP в облаке — Bilem Cloud»** — галочка «Включить» в заголовке блока (как включение на вкладке SMTP).

- Выключена: одна-две строки, что даёт облако (WhatsApp, Telegram, ChatGPT, claude.ai — без открытия базы наружу), ссылка на кабинет, «локальный MCP при этом выключится».
- Включена (подтверждение «Локальный MCP будет выключен. Продолжить?»):
  - «Облако:» `https://mcp.bilem.ai` — прописано, только чтение (адрес в конфиге, для стенда можно подменить);
  - «Логин:» — e-mail, с которым входят в кабинет;
  - общий статус + «связь: N с назад»;
  - **таблица баз этого компьютера**: база · состояние в облаке · кнопка «Подключить…» / «Отключить»;
  - после первой подключённой базы — облачный адрес организации (отдаёт облако, вида `https://mcp.bilem.ai/<org>`) с «Скопировать» и строкой «для ChatGPT и claude.ai: токена нет, вход через Google / Microsoft; WhatsApp и Telegram — в кабинете».
- Сняли галочку (подтверждение): облачный канал закрыт, подключения баз сохраняются (вернули галочку — код повторно не нужен, если облако не отозвало ключ), локальный MCP включён.

## Подключение базы

1. «Подключить…» у базы → агент просит у облака заявку на подключение (имя компьютера, база: имя/конфигурация/организации, логин) и открывает в браузере `app.bilem.ai/connect?…`.
2. В кабинете (вход Google / Microsoft) человек видит «Компьютер X просит подключить базу Y к вашей организации» и код (8 символов, 10 минут, одноразовый). Это сторона Воздуха.
3. Окно агента: база, логин, «1. Открыли кабинет — войдите и подтвердите [Открыть ещё раз]», «2. Вставьте код», [Подключить].
4. Агент обменивает код на **постоянный ключ** (один на компьютер + привязки баз — [протокол](/stand/cloud-channel-protocol)). Ключ хранится как остальные секреты агента (`Secrets`, DPAPI), в логи и sysinfo не попадает.
5. Дальше служба держит канал сама. Отключить базу можно из агента и из кабинета (агент покажет «отключена в кабинете»).

## Облачный канал в службе

- Служба (часть I, `Bilem.Agent.Service`) в режиме Cloud **сама открывает исходящее соединение** к `mcp.bilem.ai` по TLS, входящих портов нет. По каналу приходят вызовы тех же инструментов MCP, что и локально, — **только к подключённым базам** и с теми же правилами «Доступа» (чтение, белый список записи, аудит). Запрос к неподключённой базе — отказ на стороне агента, даже если облако ошиблось.
- Переподключение само, с паузами; прокси Windows учитывать.
- Статусы в агенте: «Работает · N баз в облаке», «На паузе — проверьте кабинет» (облако сказало: не оплачено / лимит), «Нет связи с облаком» (с временем последней связи и ссылкой «Диагностика»), «Отключена в кабинете» (по базе). Статус — и в трее (цвет иконки), и в строке состояния, и в sysinfo.

## Чего не делать

- Не показывать в агенте тариф, сроки, цены.
- Не держать локальный MCP и облачный канал одновременно.
- Не открывать входящих портов и не писать ключ канала в логи, sysinfo, отчёты.
- Не отдавать в облако данные неподключённых баз и ничего сверх ответа на конкретный вызов (никакой фоновой выгрузки).
