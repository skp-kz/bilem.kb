## Принцип: потребность, а не количество

- **Новая функция появляется, когда её просит живой человек** — директор, бухгалтер или бета-тестер — и мы понимаем, какой ответ он ждёт. Не «в 1С это есть, давайте выведем».
- **Консультанты решают, что важно.** Бухгалтер и руководитель на своей базе говорят: что спрашивают каждый день, где ответ неверный или бесполезный. Мы как разработчики решаем, как сделать.
- **Одна функция — до конца:** ТЗ → Земля → бета через «Обновить» → проверка на учебной и боевой базе (сходится с отчётом 1С) → документация. Потом следующая.
- **Учёт не трогаем.** Читаем, печатаем то, что уже есть в 1С, отправляем по почте. Проведение, платёжки, зарплату делает бухгалтер ([0002](/decisions/0002-ne-trogaem-uchet)).
- **Честная дата.** Каждый ответ с цифрами говорит «данные 1С на …» и предупреждает, если выписки давно не загружали.

## Работает — Bilem Agent 0.3

| Что спрашивает человек | Инструмент MCP |
| --- | --- |
| «Какие базы ты видишь?», «к какой базе подключён?» | `list_bases`, `whoami` |
| «Сколько денег на счетах и в кассе?» — с датой «данные на …» | `cash_balance` |
| «Найди “Альфу”» / по БИН | `find_counterparty` |
| «Дай последний счёт “Альфе”» → PDF с логотипом, печатью, подписью | `print_invoice` |
| «Распечатай доверенность Иванову» → PDF (форма Д-1) | `print_power_of_attorney` |
| «Сделай акт сверки с “Альфой” за квартал» → PDF | `print_reconciliation` |
| «Отправь это им на почту» — счёт и акт на любой адрес, доверенность — только на свои | `send_document` |

Плюс в программе: вкладка «Доступ» (что видит ИИ), «Печатные формы», SMTP, журнал аудита, обновления кнопкой из GitHub.

## Кандидаты — ждут подтверждения консультантов

Не берём, пока бухгалтер или руководитель не скажет «нужно, спрашиваю часто» и не покажет, какой ответ правильный.

| Что могут спросить | Чья гипотеза |
| --- | --- |
| «Какая выручка за месяц? Кто больше всех покупает?» | директор |
| «Какие налоги платить и когда?» | бухгалтер |
| «Оплачен ли счёт №…?» / «какие счета на оплату ещё не оплачены» (работа по предоплате) | бухгалтер, менеджер |
| «Напомни должнику» — акт сверки + письмо одним действием (уже собирается из `print_reconciliation` + `send_document`) | директор |
| «Как дела в фирме?» — деньги, долги, выручка одним сообщением | директор |

Черновики документов в 1С (контрагент по реквизитам, счёт) — отдельное решение, механизм подтверждения не утверждён ([ТЗ v0.3, часть B](/stand/agent-app-v03)).

## Bilem Cloud — идеи для платной версии

- **`request_feature` — «закажите вопрос» (решение Славы 19.10).** Когда у ИИ нет подходящего инструмента, он предлагает: «Этого я пока не умею — отправить разработчикам?» По согласию пользователя уходит только текст вопроса и тип базы (без данных 1С) → карточка в Inbox bilem.dev; Кура раз в день склеивает дубли и считает голоса, в работу — самое частое. Только в Cloud: бесплатный агент по принципу ничего не отправляет в сеть сам. В бесплатной версии — кнопка «Предложить вопрос» → GitHub Discussions «Идеи».
- Обещание для подписчиков: «Скажите, какой вопрос вы задаёте 1С чаще всего — через неделю Bilem будет на него отвечать».

## Чего нет и не будет

Проведение документов, платёжки, ПКО и РКО, начисление зарплаты, кадровые приказы, закрытие месяца, изменение и удаление данных. На такой запрос агент отвечает: «Это делает бухгалтер в 1С».

## Консультанты и бета-тестеры

- **Зимин** — бесплатный бета-тестер, свой OpenClaw; база — у него или на нашем сервере, его бухгалтеру — RDP. Карточка на bilem.dev → Dev → «На подходе».
- Ищем ещё: 1–2 бухгалтера на БП КЗ 3.0 и 1–2 руководителя (пост для бета-тестеров в Facebook).
- Обратная связь — GitHub Обсуждения или напрямую Славе; каждое «нужно» записываем в таблицу кандидатов с именем и примером вопроса.
